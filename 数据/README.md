# 数据说明

`E001_materials.csv` 是草案材料，12 行对应 6 组 A/B，不是评分数据。冻结时另存 `E001_materials_v1.csv`；后续修改保存 v2，不覆盖已经使用的版本。

`ratings.csv` 只有表头。一次参与者评价一条材料占一行。`annotations.csv` 也是空表，供机制、触发词、人物关系与场景标注。

## 评分字段

| 字段 | 意义与规则 |
|---|---|
| experiment_id | 例如 E001 |
| materials_version | 实际展示的冻结材料版本，例如 v1 |
| participant_id | 匿名编号，例如 R001；不写群昵称 |
| list_id / order_id | L1 或 L2；O1—O6，见实验方案 |
| pair_id / variant | P01—P06；A 或 B |
| position | 实际阅读位置 1—6 |
| funny / understood / surprise | 好笑、理解、意外；0—6 整数或空缺 |
| discomfort / want_more / naturalness | 不适、愿再听、自然度；0—6 整数或空缺 |
| seen_before | 是、否、不确定或空缺 |
| reaction | 无反应、微笑、出声笑、未观察；远程纯文字用未观察 |
| comment | 可选反馈，不记身份信息 |
| include | 1 纳入或 0 排除；最终分析判断须有记录 |
| exclusion_reason | 排除时必填；不能因为不好笑而排除 |

唯一键为 `experiment_id + materials_version + participant_id + pair_id`。同一人在同一版本中不能出现同组 A/B 两行。完整样本预计 144 条评价；缺失时保留实际数量，不补造记录。

字段值若含英文逗号、换行或双引号，按 CSV 规则用双引号包裹，内部双引号写两次。建议 UTF-8 编码；如果表格软件打开乱码，用“从文本导入”并选择 UTF-8。

## 标注字段与工作流程

参考 Zhang 等（2019）的中文幽默标注思路：[论文](https://aclanthology.org/D19-1673/)。本项目字段是适配版，不是其原标注体系的复刻。

`source_type` 区分本人创作、AI生成、授权摘录、公开来源；`source_url` 对外部材料记录可追溯网址；来源和内容使用条件分别记录，不能将公开可见等同于任意再发布。

`expected_reading` 写原先预期，`alternative_reading` 写后续解释，`trigger_words` 记触发转向的词，`mechanisms` 使用机制地图标签，多标签用中文分号。`target` 记录玩笑指向自己、物件、共同情境或他人。

正式建立案例库时，先让两位编码者独立标注同一小批材料，原始分歧分别留行，用 `coder_id` 区分；再修订操作定义。协商后的统一标注另外保存，不覆盖原始版本。不把“大家讨论后同意”叫作独立一致性。

## 分析时避免这些错误

同一人的六次评价不是六个独立的人。每条材料同时有很多人的评价，材料也不是无限多。首轮以参与者差值和逐材料描述为主，结论限定在当前材料；扩展后可使用参与者和材料交叉的层级模型。

汇报每组的评分分布，特别是两极分化。一半给 0、一半给 6，和人人给 3，不是同一件事。缺失不记零；笑声未观察不写“无反应”；不按结果临时删低分受众。

人和 AI 的评分分开存；演示数据与真实数据分开存。当前文件均不包含真实参与者记录。
